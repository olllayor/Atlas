Tool-step budget: before vs after

Atlas agents were dying mid-task because stepCountIs(64) (32 on lightweight models) hard-stops the stream with no wrap-up and no durable reason. Claude Code’s Agent SDK solves this with taskBudget: the model knows remaining budget and finishes cleanly. This change ports that idea, then persists the stop if the cap is still hit.

The two paths

BEFORE Silent mid-task stop

1
Agent tools through the task 64 tool steps (32 if flash/mini/haiku/turbo)
2
Budget burns with no signal Model never told remaining steps. Keeps exploring.
3
stepCountIs() hard-stops Stream ends mid-chain. No final summary.
4
Notice is ephemeral “Reached the step limit…” lives only on the live draft.
5
Turn settles, reason gone User sees a completed-looking answer that just stopped.

AFTER Budget-aware wrap-up

1
Agent tools through the task Same 64 / 32 hard cap. Safety net unchanged.
2
Wrap-up window opens Last 8 steps (or 25%): remaining budget injected each step.
3
Model finishes or reports Near 1–2 left: stop new work, write progress + next steps.
4
If cap still hits: notice persists Appended as trailing text part on the assistant message.
5
Transcript and next turn keep the reason User sees why. Model history can continue from there.
Claude Code reference. taskBudget in @anthropic-ai/claude-agent-sdk: “the model is made aware of its remaining token budget so it can pace tool use and wrap up before the limit.” Hitting maxTurns returns typed error_max_turns, not silence.

Budget numbers

Model tier Hard cap Wrap-up window Warn starts at step Before
Standard / heavy 64 8 steps step 57 No warning, silent stop
Lightweight (flash/mini/haiku/turbo) 32 8 steps step 25 No warning, silent stop
Tiny test limit (3) 3 2 steps step 2 No warning, silent stop

User-visible outcome

Situation Before After
Agent wraps up in time N/A (never told to wrap up) Final summary in the message
Cap still hit Looks like a normal completed stop Trailing text: “Reached the step limit (N)… reply continue”
Next turn after a stop Model has no stored stop reason Reason is in assistant history
Live streaming UI Transient draft notice only Same live notice + durable part
