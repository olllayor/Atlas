Anatomy of the T3 Code hover architecture

1. Three-tier card row

Unlike Atlas's single-line row, T3 Code gives each session roughly 60px height: Project and Settle action on line 1, full user prompt on line 2, and Git branch on line 3. High upfront context at the cost of vertical list density.

2. Proactive branch mismatch warning

The hover card compares the session's recorded branch against local Git HEAD. If they differ, an amber warning states: “You're currently checked out on another branch.” This protects against cross-branch pollution before the user clicks.

3. First-class model chip

The model (e.g. Muse Spark 1.2 Free) is rendered explicitly on the hover card. In Atlas, this was previously hidden in a native HTML title attribute on the title, making it unreachable on touch or quick glance.

4. “Settle” workflow vs. “Archive”

T3 Code provides a direct checkmark “Settle” button on the row. Completed work moves into the “Settled (11)” accordion. This treats sessions as work units that reach completion rather than discarded chat transcripts.
