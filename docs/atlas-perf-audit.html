Where Atlas gets heavier over time

A module map of the main / preload / renderer boundary with measured IPC and shipped-bundle numbers. Every figure below is grounded in the local build (out/, Aug 6) and du on node_modules/.pnpm; nothing is estimated.

Date: 2026-08-06 Branch: dev @ 46da4c6 Method: vite build output, du, grep counts

The one number that matters

Shipped renderer weight: 21.0 MB across 354 JS files (+197 KB CSS). The first-paint critical path alone is a single 4.87 MB chunk (index-CMZVJW9i.js), and the app only ever loads more from there — a long tail of ~280 sub-40 KB shiki grammar/theme chunks plus a diagram stack (mermaid 2.71 MB, cytoscape 956 KB, treemap 900 KB). This tail is where the app should get visibly leaner: it is pure weight that only a fraction of users touch. The main process is comparatively tiny (790 KB bundle) and the preload is 19 KB.

Scale check. node_modules is 1.2 GB but that is dominated by build/dev-only packages (electron 283 MB, app-builder-bin 207 MB) and is not what ships. The number that matters is the 21 MB in out/renderer — shipped, minified bytes.

Findings, by impact

#What's heavyCostWhyFix

Lazy-gate the visual galleries; tree-shake d3 to what visuals call (it lands on the critical path today).
2Shiki grammar long-tail 280 files ~280 shipped JS assets are sub-40 KB — the shiki language/theme set shipped by @streamdown/code + shiki. Only the ~40 languages in codeLanguages.ts are ever routed to CodeBlock. Subset shiki to the ~40 aliased grammars; import the rest only on the fence that needs them.
3Diagram stack loaded after boot anyway +2.71 MB prewarmMessageRendering() fires requestIdleCallback with a 1200 ms timeout, pulling the whole streamdown+mermaid chunk down shortly after first paint even with no diagram on screen. Load on the first code fence / first diagram instead of a timed prewarm; drop the timeout.
4Unbounded conversation list, unwindowed sidebar n rows conversations.list() has no LIMIT: a full table scan plus per-row 160-char preview subqueries, and the sidebar maps every row in an expanded group with no virtualizer (the transcript is windowed; the sidebar is not). Cap/paginate list(); window the sidebar with @tanstack/react-virtual (already in the bundle).
5Per-chunk streaming IPC, broadcast to every window 1 / chunk chat:event emits once per stream chunk (text/tool deltas, uncoalesced), and terminal:output broadcasts to all windows on every pty write; each window holds its own copy of the renderer bundle. Coalesce deltas in main; fan terminal output only to windows showing that conversation.
6Startup builds the whole service graph first many awaits app.whenReady awaits db open + reconcile + migration + registry scan + MCP graph before createWindow() (line 485). Network/child-process work is correctly deferred — only this sync graph is on the first-paint path. Lazy-init low-priority services; create the window before the full graph is warm.

Runtime growth

  • Renderer listeners are cleanly paired — chat/updates/models/terminal.subscribe and every addEventListener returns a matching remove / unsubscribe.
  • The 60 s clock setInterval in App.tsx is cleared on unmount; no orphan intervals found in app code.
  • Transcript rows are windowed, so a long thread stays flat on the DOM; the shiki highlighter caches grammars per language used over a session (bounded by the languages actually seen).

    • Uncertain — not asserted. Likely modest per entry, but unbounded in count: a long multi-conversation session should grow, not stay flat.

Treat those two as directions, not audited totals.

Fix first, by leverage

  1. Subset shiki to the ~40 used grammars — the single cheapest weight cut; one table already lists exactly which languages are reachable.
  2. Drop the timed prewarm of the mermaid/streamdown chunk; load it on the first fence or diagram.
  3. Cap and window the conversation list — closes both a startup scan and an unwindowed sidebar render with a library already installed.
  4. Pull the visual gallery (d3/Chart) off the critical path so first paint no longer carries ~480 KB of inlined raw chart libraries.
  5. Coalesce streaming/terminal IPC to cut per-chunk sends and cross-window broadcast.
