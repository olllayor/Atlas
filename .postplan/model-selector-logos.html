Model selector with provider logos

Decision is how logos structure the composer picker, not whether to use them. Atlas already ships monochrome brand marks in providerLogos.tsx. Three shapes below use those marks as navigation. Not a clone of the screenshots.

A. Icon rail filters providers

Left rail is the provider index. Right pane is one flat model list for the active rail slot. Search narrows models. Closest to the dark screenshots.

Why this shape

  • Logo is recognition, not a second navigation system.

  • Weakest when the catalog is large and users browse by vendor.

Data shape behind any variant

Same domain for all three. The layout only changes how Provider is reached.

Provider {
  id, label, logoId,
  selfManaged, configured,
  models: Model[]
}
Model {
  id, label, providerId,
  isFree, supportsVision,
  supportsReasoning, reasoningEfforts
}

Shared rules. Chip shows logo + short name + effort pill. Menu keeps Reasoning effort and Manage models. Agent and No key stay text badges. No colored logo tiles.

Recommendation

B first. It is the smallest break from the current chip + menu, uses logos as real filters, and stays compact above the composer. A if the provider list regularly exceeds eight. C if you want the least new chrome and mostly search by name.
